## What this product is

Project GM is a conversational fantasy RPG backend where an AI narrates but a deterministic Game Engine
owns all truth (see `ARCHITECTURE_CONTRACT.md`). All agent-relevant context lives in two levels:

| Level | Location | Answers |
|-------|----------|---------|
| **Product level** | `docs/` | What is the product? How do the repos fit together? What rules apply everywhere? |
| **Repo level** | `<repo>/docs-agent/` | What is this repo? How is it built? How do I change it safely? |

Start at [`docs/index.md`](docs/index.md) — it routes you to the right file for your task.

## How this context was created & how to keep it fresh

This `docs/`/`docs-agent/` layer was authored directly from the codebase by an AI agent on request
(2026-09-21), not generated by the kit's automated 8-stage pipeline (`pc-intake`/`pc-clone-repos`/etc. —
those tools are not wired up in this workspace). All content should be traceable to real code/config, not
invented.

To keep it accurate: when behavior changes, ask an agent to review and update the specific
`docs-agent/*.md` (or `docs/*.md`) file affected — there is no automated re-seed/validation step here,
it is maintained the same way it was created: manually, on request.
